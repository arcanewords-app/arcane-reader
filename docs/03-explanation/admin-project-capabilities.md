# Возможности админа по проектам

Рабочая записка по коду на 2026-10-06. Код важнее этой заметки: `src/client/pages/AdminProjectCardPage.tsx`, `src/client/pages/AdminProjectsPage.tsx`, `src/services/supabase/domains/admin.ts`, `src/services/supabase/domains/projects.ts`. Политика доступа: [[_canonical/rules/security]], роли: [[_canonical/rules/auth]], карта маршрутов: [[_canonical/rules/routing]].

**Вывод:** админ видит все проекты, может снять публикацию или удалить проект и правит публичную карточку чужой работы на `/admin/projects/:projectId`. Обычное окно `/projects/:id` чужую работу не открывает. Запись идёт отдельными admin-маршрутами, авторские проверки владельца не ослаблены.

## Что админ может сейчас

Вкладка `/admin/projects` закрыта `AdminGate` и `requireRole('admin')`. Список читает service role. RLS при этом не применяется: service role его обходит, и только на сервере.

На вкладке проектов админ может:

- видеть все проекты: имя, email владельца, языки, число глав и переведённых, статус публикации
- копировать id проекта
- открыть карточку `/admin/projects/:projectId`
- открыть публичную страницу каталога, если работа опубликована
- снять публикацию
- удалить проект, в том числе опубликованный, после подтверждения

Снятие с публикации и удаление пишутся в лог как `admin.project.unpublish` и `admin.project.delete`, с `adminId`. Правка карточки пишется как `admin.project.card` со списком полей.

Рядом, на других вкладках `/admin`:

- сущности каталога: теги, авторы, переводчики
- новости
- список публикаций и снятие с публикации
- пользователи и смена роли: нельзя снять админа с себя и нельзя убрать последнего админа
- модерация заявок на перевод

На **своём** проекте админ может назначить любого активного переводчика из каталога. На чужой проект то же правило действует только на карточке модерации, не в авторском окне.

## Почему обычное окно проекта не подходит

Страница `/projects/:id` пускает админа: `AuthorGate` проверяет роль не ниже автора, а админ выше. Дальше каждый запрос ищет проект по `user_id` из JWT, не по роли. `getProject` фильтрует `.eq('user_id', userId)`. То же для глав, глоссария, настроек, публикации и перевода. Чужой id вернёт пусто или 404.

RLS на `projects`, `chapters` и `glossary_entries` смотрит только `auth.uid() = projects.user_id`. Роли админа в политиках нет. Клиентский ключ чужой проект не откроет. Service role политики обходит, поэтому новые админские действия должны оставаться за `requireRole('admin')` и не открываться клиентским ключом.

Политика BOLA: владение проверяется в запросе. Исключение для админа — отдельный маршрут с журналом, а не пропуск проверки владельца на авторских API.

Полное окно редактора задело бы перевод, удаление глав, настройки моделей и расход кредитов. Кредиты считаются на пользователя из JWT. Если админ переводит чужой проект, неясно, чей лимит списывать, и след в логах смешается с действиями владельца.

Вход под чужим пользователем хуже: это чужая сессия, а не админское действие.

## Выбранный вариант

Сделана урезанная карточка, не полное окно проекта.

Страница `/admin/projects/:projectId` за `AdminGate`. На ней можно менять название проекта и название в каталоге, описание, обложку, автора, переводчика, теги, статус перевода и ссылку на источник. Email владельца только для чтения. Глав, глоссария, настроек, перевода и кредитов нет.

Запись:

- `GET /api/admin/projects/:id` — поля карточки и статус публикации, без текста глав
- `PATCH /api/admin/projects/:id/card` — строгий список полей, не свободный `metadata`
- `POST` и `DELETE /api/admin/projects/:id/cover` — та же проверка файла, что у авторской обложки, без проверки владельца

Всё под `requireRole('admin')`, запись через service role. Если строка `publications` есть, те же поля сразу попадают в каталог. Пустое значение снимает поле. После записи сбрасываются кэши проекта владельца и публикации.

Переводчик принимается, если сущность активная и `kind = translator`. Автор и теги — активные сущности своего вида.

## Что по-прежнему не делаем

1. **Только просмотр глав** для поддержки без записи и без запуска перевода.
2. **Полный редактор на отдельных admin API.** Сначала решить, чей кредит тратится, и писать аудит на каждую запись.
3. **Не делать:** открывать `/projects/:id` для чужого проекта и входить под владельцем.
